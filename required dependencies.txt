TEAMVERITY - VERITY DRIVE
REQUIRED DEPENDENCIES

Repository: https://github.com/CAdinaDenisa/DataInfrastructure_TeamVerity
Source baseline: main, commit 9352946af6e8a1b01d45f3ce95e5772622165665.
Use each application's package.json and package-lock.json as the authority.
The versions below are the lockfile-resolved direct dependencies at this commit.

1. SOFTWARE REQUIRED BY ROLE

All developers:
- Git, repository read access, Node.js 24.x, and the npm bundled with Node.
  Node 24 matches the submitted CI workflow and Azure Functions configuration.
  The backend manifest declares >=20, but Node 24 is the common project target.
- VS Code or another text editor. A current Chrome, Edge, Firefox, or Safari
  browser is needed for the dashboard; WebGL support is needed for its 3D view.
- Install packages separately in src/backend/api, src/web, and src/phone-app.
  There is no root npm workspace/package.json install step.

Ana / mobile demo:
- A physical Android or iOS phone and an Expo Go version compatible with this
  project's Expo SDK 58. If the installed Expo Go cannot run SDK 58, use a
  compatible Expo development build rather than changing dependency versions
  immediately before the demo.
- Internet access for Azure requests and development connectivity to Metro.
  Use LAN or Expo's tunnel option when appropriate.
- Accelerometer availability is required by the current capture path.
  Magnetometer, barometer, and GPS features depend on hardware/permissions;
  missing optional sensors are reported explicitly by the app.
- Two physical phones with different configured VINs are needed to demonstrate
  two concurrent real sensor streams. The backend simulator is a separate
  testing aid and must not be presented as a second physical phone.

Stefana / local backend:
- Azure Functions Core Tools v4 when running npm start / func start directly.
- Docker Desktop with Docker Compose v2 (or equivalent Linux Docker setup)
  for the supplied SQL Server/Azurite local environment.
- SQL Server container image: mcr.microsoft.com/mssql/server:2022-latest.
  The compose file uses linux/amd64. An x64 environment is the reference path;
  the team must separately verify any ARM/emulation setup.
- Azurite container image: mcr.microsoft.com/azure-storage/azurite.
  It emulates Functions host storage, not the production telemetry database.
- For memory-mode development without Docker, a separately running Azurite
  installation can provide host storage; SQL Server is then unnecessary.

Adina / cloud provisioning and deployment:
- Azure CLI with Bicep support, or Azure Cloud Shell using PowerShell.
- An Azure subscription permitting the selected services/locations.
- Resource creation permissions, plus permission to assign the scoped Azure
  roles included in the Bicep templates and GitHub identity setup.
- A Microsoft Entra SQL administrator for database migrations and the Function
  App database-user grant. Azure resource permissions alone do not grant SQL
  data/schema permissions.
- GitHub repository access sufficient to create Actions variables and review
  or merge the workflow. GitHub-hosted runners require no self-hosted runner.
- Existing or newly created OIDC identity teamverity-github, federated to the
  repository's main branch. No Azure client secret/SWA token is required.

2. BACKEND PACKAGES - src/backend/api

Production dependencies (installed by npm ci):
- @azure/functions 4.17.1: Node.js Azure Functions v4 HTTP registration/runtime API.
- @azure/identity 4.14.1: Azure credential chain used for passwordless SQL access.
- mssql 11.0.2: SQL Server / Azure SQL client and connection pooling.
- ajv 8.20.0: JSON Schema validation.
- ajv-formats 3.0.1: format validators used with Ajv.

The default automated tests use Node's built-in node:test and assert modules.
No Jest/Mocha installation is required. The deployment installs production
packages with npm ci --omit=dev. SQL integration checks additionally require a
reachable, migrated SQL database; the default CI tests do not prove live SQL.

3. MOBILE PACKAGES - src/phone-app

- expo 58.0.26: Expo SDK and development CLI integration.
- react 19.3.0: component/state model.
- react-native 0.88.1: native mobile UI/runtime.
- expo-sensors 58.0.5: motion, magnetic, and pressure sensor access.
- expo-location 58.0.22: foreground GPS/location access.
- expo-secure-store 58.0.3: persistent internal phone identifier.
- expo-crypto 58.0.8: declared Expo crypto capability.
- expo-status-bar 58.0.5: status-bar presentation.
- @react-native-async-storage/async-storage 2.2.0: VIN/event-queue persistence.
- react-native-safe-area-context 5.11.1: safe-area layout handling.
- @expo/ngrok: development dependency declared as ^4.1.3, used for Expo tunnels.

The Expo CLI is invoked through npx expo; installing the legacy global expo-cli
is unnecessary. EAS CLI/native Android/iOS build tools are optional for the
Expo Go path, and required only if choosing the corresponding native build
workflow. Expo's Metro tunnel does not expose a separate local backend API.

4. DASHBOARD PACKAGES - src/web

- chart.js 4.6.1: chart rendering.
- three 0.187.0: 3D rendering; OrbitControls is copied from the same package.
- http-server: development dependency declared as ^14.1.1; npm start serves
  the dashboard on port 5173.

npm ci runs the vendor-copy postinstall script. npm run build produces dist/.
The browser loads the copied modules; no React, Vite, or separate transpiler
is required for this frontend.

5. CLOUD AND RUNTIME CONFIGURATION DEPENDENCIES

These are operator configuration values, not npm packages:
- SQL_SERVER: real Azure SQL server FQDN.
- SQL_DATABASE: telemetrydb for the reference deployment.
- STORAGE_MODE: azure-sql in Azure (health reports storageMode: sql).
- DEMO_TENANTS_JSON: valid JSON array containing owner IDs, real SHA-256 token
  hashes, explicit authorized VINs, and optional future expiry timestamps.
- Function host managed-identity storage settings, created by main.bicep.
- SQL schema migrations and the Function App identity database grant.
- Exact dashboard browser origins permitted by Function App CORS.
- EXPO_PUBLIC_API_URL in src/phone-app/.env: actual API HTTPS base URL.
- apiBaseUrl in web config.js: actual API base URL including /api.
- GitHub Actions variables: AZURE_CLIENT_ID, AZURE_TENANT_ID,
  AZURE_SUBSCRIPTION_ID, AZURE_RESOURCE_GROUP, AZURE_FUNCTIONAPP_NAME,
  AZURE_WEB_STORAGE_NAME, and ENABLE_DEPLOY.

A token hash placeholder such as HASH-UL-EXISTENT is not a credential and is
rejected by the backend parser. Obtain the original owner token privately;
only its hash belongs in Azure's tenant configuration.

6. DEFAULT LOCAL PORTS

- 7071: Functions HTTP API.
- 5173: dashboard development server.
- 1433: local SQL Server.
- 10000 / 10001 / 10002: Azurite Blob / Queue / Table emulation.
- 8081: usual Metro development port; use the actual address printed by Expo.

A physical phone cannot use localhost to reach the developer's laptop. Use
Azure HTTPS or an explicitly configured reachable LAN/API tunnel address.

7. INSTALLATION POLICY

Run npm ci in each application directory so its lockfile controls installation.
Do not manually install dependency names/versions one by one. If npm ci reports
a manifest/lockfile mismatch, the owning teammate must reconcile and commit the
pair. For intentional Expo package changes use the compatible Expo tooling,
review the resulting lockfile, and retest on the actual phone.

Optional VS Code extensions: Azure Functions, Bicep, SQL Server (mssql), and
Docker. They improve the development experience but are not imported runtime
dependencies. No paid editor extension is required.
